# Routing Rules

Rules that map classifier and extractor outputs to actions. Used by the Action/Decider Agent. Aligned with action set and escalation contract.

## Inputs to Action/Decider

- **intent** (from Classifier): support | sales | contract | technical | billing | spam | unknown | multi_intent.
- **confidence** (from Classifier): [0, 1].
- **extracted_entities** (from Extractor): optional; used for routing refinement (e.g. product category).

## Default Rule: Escalate by Default

- **unknown** or **multi_intent** → action = **escalate**. escalation_reason = ambiguous_intent or multi_intent per escalation contract.
- **confidence** below threshold (see intent-taxonomy) → action = **escalate**. escalation_reason = low_confidence.

## Intent → Action Matrix (High Confidence)

| Intent | Typical action | Notes |
| ------ | ----------------- | ------ |
| support | route_to_queue | Queue: support (or tenant-specific queue). |
| sales | route_to_queue | Queue: sales. |
| contract | escalate | Contract changes and legal-sensitive; human-in-the-loop. |
| technical | route_to_queue | Queue: technical. |
| billing | route_to_queue | Queue: billing. |
| spam | route_to_queue | Queue: spam_review or tenant-specific triage. Any internal discard is an implementation detail behind this routed path and must still be logged. No customer-facing reply for spam. |

## Overrides

- **contract** intent: always escalate (compliance, brand).
- **Complaint** or **legal** signals (from extractor or keyword rules): escalate; escalation_reason per escalation contract.
- **Policy-sensitive** content: escalate; do not auto_respond without explicit business rule.

## Business Units and SLAs

- Queue names and SLA targets are configurable (e.g. via env or tenant config); no hardcoded queue IDs in this contract. Document in operations runbook.
- Mapping from intent/action to business units must be documented where deployment config lives (this codebase only; prod nginx is regenerated by deployment scripts).

## Naming

- Use only business scenario vocabulary: support, sales, contract, technical, billing, spam, escalate, route_to_queue, auto_respond.
